# Story 0.0.0: Author the GitHub manual-setup runbook (`ctam-architecture/runbooks/github-setup.md`)

Status: ready-for-dev

## Story

As a **platform engineer**,
I want a single manual GitHub web-UI setup runbook covering repo creation, branch protection, team access and the per-repo agent-enforcement wiring,
So that **every one of the 16 repos is created identically and safely without the `gh` CLI, and no scaffold story has to reverse-engineer its own preconditions**.

## Acceptance Criteria

1. **Given** the `gh` CLI is unavailable to engineers and denied to agent sessions (**D10**; enforced by `_arch/agent-rules/enforcement/claude/hooks/block-git-writes.sh`, which denies all `gh`/`hub` subcommands),
   **And** the runbook is written at `ctam-architecture/runbooks/github-setup.md`,
   **When** an engineer follows it to create a new CTAM repository,
   **Then** it documents creation **via the GitHub web UI** under the HMCTS org — **private**, named per the CNP convention (`ctam-<service>`; `{product}-shared-infrastructure` for the shared estate),
   **And** it states explicitly that the HMCTS template's `setup-new-repo.sh` **must not** be used, because it makes the repository **PUBLIC**,
   **And** it documents branch protection on `main` via *Settings → Branches*: require PR review, require status checks, require linear history,
   **And** it documents `CODEOWNERS` and team access scoped to the owning team (per AR29),
   **And** no step anywhere in the runbook invokes `gh`.

2. **Given** the repository exists and is empty,
   **When** the engineer moves on to scaffolding,
   **Then** the runbook states the boundary explicitly — `ctam-scaffold.sh` performs **local** scaffolding and pushes to the **pre-created** remote over plain `git`; it never creates or configures a repository,
   **And** the runbook names itself the precondition of Stories 0.0.1, 0.1.1, 0.2.1, 0.2.4 and 0.5.1, so the dependency is documented in one place rather than restated in five.

3. **Given** a newly created repository must be able to host a cold agent session,
   **When** the engineer completes the per-repo wiring section,
   **Then** the runbook documents pinning the context bus — `git submodule add` of `ctam-architecture` at `_arch`, checked out at an exact `arch-vN` tag — and that the pin moves only by an explicit, recorded bump,
   **And** it documents generating `CLAUDE.md` from `_arch/agent-rules/enforcement/claude/CLAUDE.md.template`, substituting `{{SERVICE_NAME}}` and `{{ARCH_VERSION}}` and changing nothing else,
   **And** it documents copying `.claude/settings.json` from `settings.json.template` together with the `hooks/` directory, and making the hooks executable,
   **And** it records how to verify the wiring actually took: a session in the new repo is **denied** a commit while HEAD is on `main`.

4. **Given** the runbook is complete,
   **When** it is published to the bus,
   **Then** it is linked from `_arch/agent-rules/index.md` and from `architecture/starter-template.md`, so a session finds it without knowing the path,
   **And** it carries the `arch-vN` tag it was published under, since downstream repos pin the bus by tag.

## Dev Notes

**This packet targets the context-bus repo itself (`ctam-architecture`), not a service repo.** Three consequences, all of which differ from every other CTAM packet:

- **There is no `_arch/` submodule here** — the bus cannot submodule itself. Every path in this packet is **repo-root-relative**: the rules are at `agent-rules/…` and the architecture at `architecture/…`. If you find yourself looking for `_arch/`, you are in the wrong mental model.
- **There is no `CLAUDE.md` and no `.claude/hooks/` in this repo.** `CLAUDE.md.template` is written for `ctam-{service}` execution units, and nobody has authored a bus-repo equivalent. So no rules load automatically and **`block-git-writes.sh` is not installed here** — the `main`-branch discipline in **R13**/**W7** is on you as the operator, not enforced by a hook. Do not commit to `main`. You are on `story/0.0.0`; stay on it.
- **`agent-rules/index.md` binds only the twelve Java execution units** (`ctam-mock-auth` … `ctam-mi-feed`), and explicitly records `ctam-ui`, `ctam-admin-ui` and `ctam-shared-infrastructure` as *not yet covered*. `ctam-architecture` is not in either list. The **core rules R1–R14 still bind your conduct**; the Java- and test-specific rules do not apply to a Markdown deliverable. See *Definition of done* below for exactly which gate items are waived.

The acceptance criteria above are **verbatim from the epic** and are never edited (**W8**). They were authored assuming a *service* repo, so four clauses name `_arch/…` paths and one names `ctam-architecture/runbooks/…`. **In this repo those prefixes do not resolve** — the bus cannot submodule itself, and you are already inside `ctam-architecture`. ### Context distilled from the bus

Read at the pin, `arch-v1.1` (`git show arch-v1.1:<path>`). At the time of dispatch the `arch-v1.1` tree is **identical to `main`**, so the working tree is a faithful copy of the pin.

- **The `gh` prohibition is real and enforced, not advisory.** `agent-rules/enforcement/claude/hooks/block-git-writes.sh` denies `gh`/`hub` outright, with the recorded reason: *"repository administration, PR approval and merge are the human gate itself"* — and, directly relevant to AC-1, *"the HMCTS template's `setup-new-repo.sh` makes a repository PUBLIC, which is another reason `gh` stays closed."* That sentence is the authority for the prohibition the runbook must carry; quote it.
- **The bus-pinning rule** (`architecture/delivery-operating-model.md` → *The bus-pinning rule*, canonical in the control plane): *"A service repo re-syncs to a newer `ctam-architecture` version only by an explicit, committed submodule bump. The bus never mutates a downstream repo silently."* AC-3's submodule section must state this, not just the `git submodule add` mechanics.
- **Per-repo wiring layout** (`agent-rules/index.md` → *How these rules reach a service repo*) is the authoritative shape to document: `CLAUDE.md` generated from the template and naming the pinned version, `_arch/` as the submodule, `docs/stories/<id>.md` for the packet.
- **Branch naming** (`architecture/conventions.md` → *Git conventions*, amended 2026-08-20): `story/{story-id}` for dispatched story work, one branch per story from dispatch to PR; `bugfix/`, `chore/`, `feature/` for everything else. The runbook's branch-protection section should not contradict this.
- **Commit style** (same heading): Conventional Commits prefix, imperative, ≤ 72-char subject. This story's commits are `docs:`.

### Rules that apply

Core conduct rules, from `agent-rules/00-core.md` @ `arch-v1.1`. These four will actually bite on this story:

- **R4 — Cite or ask.** Every non-obvious claim in the runbook names its authority. A step that says "enable branch protection" without pointing at AR29 or the AC is a guess. This applies to the *runbook you write*, not only to your session notes.
- **R5 — Unknown means stop.** You will hit at least one genuine unknown: HMCTS org-level settings, and which team owns `CODEOWNERS` for each repo, are not recorded anywhere in the bus. Do **not** invent a team name or an org policy. Write it into *Open questions* in this packet and leave the runbook with an explicit `TBD — what is unknown, who can answer` marker, which is a documented gap rather than a fabricated instruction.
- **R6 — No unsanctioned surface.** The deliverable is `runbooks/github-setup.md` plus two link edits. Do not add a template, a script, a CI workflow or a second runbook.
- **R14 — No uninvited work.** `agent-rules/index.md` has stale frontmatter at the pin (`bus_version: unpublished (targets arch-v1.0)`) and `agent-rules/60-session-protocol.md` **W12**'s example handoff still shows `branch: feature/CTAM-123-mrd-ingestion`, which contradicts **W7**'s one-branch-per-story rule. **Both are real defects. Neither is yours to fix in this story** — record them under *Open questions*.

**R8** (nothing unfinished ships) needs one clarification for a documentation story: a `TBD` marker that AC-1 through AC-4 do not require, and that R5 forces you to record, is *not* an R8 violation — it is the honest output of a stop. A vague sentence that pretends to be an instruction is.
